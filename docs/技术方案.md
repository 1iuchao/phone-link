# 手机投屏软件 技术方案与实施计划（v1）

## 一、背景与目标（Context）

用户需要一个 Windows 端软件：Android 手机（当前 iQOO Neo8 / V2301A / Android 16 / SDK 36）与电脑在同一网络时，在电脑上显示手机屏幕；声音可选手机端、电脑端或两端同时；同时支持 USB 有线连接；并能在电脑上反向控制手机（鼠标 + 键盘，含中文输入）。

前期已完成技术选型与**全部功能实测**，本方案是把验证成果做成一个可日常使用的原生 Windows 应用。

目标形态：**绿色版目录**，双击即用，不安装、不依赖额外运行时；不投屏时应用不驻留、不占资源。

## 二、已验证结论（实测，作为设计依据）

| 能力 | 实现方式 | 状态 |
|---|---|---|
| 有线投屏 | scrcpy over USB（自带 adb） | 通过 |
| 无线投屏 | `adb tcpip 5555` + `adb connect <IP>:5555`；Android 11+ 可用系统「无线调试」配对 | 通过（拔线后仍正常） |
| 反向控制（鼠标） | scrcpy 默认 | 通过 |
| 反向控制（键盘） | 必须 `--keyboard=uhid`；默认 sdk 模式会被电脑输入法截获字母，只能输入数字 | 通过 |
| 中文输入 | UHID + **把投屏窗口所在线程的键盘布局切为英文**（`LoadKeyboardLayout("00000409")` + `PostMessage(WM_INPUTLANGCHANGEREQUEST)`）；离开投屏窗口时切回中文（`00000804`）。实测 HKL 切换是**全局生效**的，因此必须做双向还原。切换过程**不新增键盘、不污染语言栏** | 通过 |
| 音频·电脑端出声 | 默认（`--audio-source=output`），手机静音 | 通过 |
| 音频·手机端出声 | `--no-audio` | 通过 |
| 音频·两端同时 | `--audio-dup`（自动切 `playback` 源，需 Android 13+；少数 App 可主动退出捕获） | 通过 |
| 音频档位切换代价 | 必须重启 scrcpy 会话，约 1 秒 | 已确认 |
| 熄屏投屏 | scrcpy 运行时快捷键 `MOD+O`（ALT+O） | 可用 |
| 保持常亮 | scrcpy 仅启动参数 `--stay-awake`，无运行时快捷键 → 改用 `adb shell svc power stayon true/false`（免重连） | 方案确定 |
| 摄像头模式 | `--video-source=camera`（需 Android 12+；音频源默认变手机麦克风；控制不可用） | 可用 |
| 窗口控制参数 | `--window-borderless`、`--window-x/y/width/height`、`--always-on-top`、`--no-window-aspect-ratio-lock` 均存在 | 已核对 |

内核版本：**scrcpy v5.0.1**，已在本机 `tools\scrcpy-win64-v5.0.1\`（含 `scrcpy.exe`、`scrcpy-server`、`adb.exe`、`SDL3.dll`、ffmpeg 相关 dll）。

## 三、技术栈与构建方案（关键约束）

**本机没有 .NET SDK**（`dotnet --list-sdks` 为空），无法使用 `dotnet build` 或 SDK 风格项目；网络很慢（实测约 27KB/s），下载 200MB+ 的 SDK 不现实。因此：

- **技术栈**：C# + **WinForms**，目标 **.NET Framework 4.8.1**（系统已装，绿色版无需装运行时）
- **编译器**：Visual Studio 2026 Build Tools 自带的 Roslyn
  `C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools\MSBuild\Current\Bin\Roslyn\csc.exe`
- **参考程序集**：直接引用系统目录
  `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\{System, System.Core, System.Windows.Forms, System.Drawing, System.Net.Http, System.Runtime.Serialization}.dll`
- **不使用 MSBuild / NuGet**：本机无 `.NETFramework` 引用程序集目录、无 NuGet 缓存且网络慢；因此**不引入任何第三方依赖**
- **已实测通过**：csc 编译 C# 最新语法（含 `switch` 表达式）、中文命名空间、中文界面、**中文路径** `e:\githubapps\手机互联`、产出 exe 可正常运行
- **构建脚本** `build.ps1`：收集 `src\**\*.cs` → 调 csc（`/target:winexe /langversion:latest /win32icon /win32manifest`）→ 输出 `dist\手机互联.exe`
- **配置持久化**：无 `System.Text.Json`，用自写的简易键值（INI）序列化，存 `%APPDATA%\手机互联\config.ini`

## 五、窗口结构与嵌入方案

**推荐方案 A：无边框 + 精确定位跟随**

- 宿主 `MainForm`：顶部自绘工具栏（约 40px）+ 下方客户区
- 启动 scrcpy：
  `--window-borderless --window-title=手机互联 --window-x/y/width/height=<客户区屏幕坐标>`
- 宿主窗口移动 / 缩放 / 缩放结束 → `SetWindowPos` 把 scrcpy 窗口同步到客户区
- 焦点链路：scrcpy 窗口仍是独立顶层窗口 → SDL 键盘输入、UHID、输入法切换目标窗口天然正确
- 置顶：`MainForm.TopMost` + 对 scrcpy 句柄 `SetWindowPos(HWND_TOPMOST/NOTOPMOST)`
- 无边框后无标题栏 → 自己实现窗口拖动（`WM_NCHITTEST` 返回 `HTCAPTION`）与最小化/关闭按钮

**兜底方案 B**：`SetParent` 真嵌入（画面严格裁剪在客户区内）。`WindowEmbedder` 预留该路径，若方案 A 出现画面溢出/焦点异常再切换。

## 六、工具栏按钮实现映射（首期）

| 控件 | 实现方式 |
|---|---|
| 音量 − / + | `adb shell input keyevent 25 / 24` |
| 同上·悬停滚轮 | WinForms 的 `MouseWheel` 只发给有焦点的控件 → 在 MainForm 实现 `IMessageFilter` 拦截 `WM_MOUSEWHEEL`，判断光标是否落在音量按钮上，是则消费并调节；80ms 节流合并连续滚动 |
| 窗口置顶 | 切换 `TopMost` + `SetWindowPos` scrcpy 句柄 |
| 重连刷新 | 优先：`SetForegroundWindow(scrcpy)` 后 `SendInput` 发送 `Alt+Shift+R`（scrcpy 的"重置视频采集/编码"）；发送失败或无效则降级为重启会话 |
| 设置（弹层，4 项） | ↓ |
| ├ 音频输出 | 三档单选（电脑=默认 / 手机=`--no-audio` / 双端=`--audio-dup`），选择后**重启会话**（保留连接方式与其它开关） |
| ├ 熄屏投屏 | 切换时向 scrcpy 窗口发 `Alt+O`，不重启 |
| ├ 保持常亮 | 开关（默认关）→ `adb shell svc power stayon true/false`，不重启 |
| └ 摄像头模式 | 开关 → 重启会话为 `--video-source=camera`；提示"音频走手机麦克风、控制不可用"，并按此置灰控制类按钮 |

## 七、启动参数生成规则

固定参数：`--keyboard=uhid --window-borderless --window-title=手机互联`

| 维度 | 取值与参数 |
|---|---|
| 连接 | 有线：`--select-usb`（或 `--serial=<USB序列号>`）；无线：`--serial=<IP>:5555` |
| 音频 | 电脑：不传（默认 output）；手机：`--no-audio`；双端：`--audio-dup` |
| 熄屏（启动期） | 开关为真时追加 `--turn-screen-off`（运行期用 ALT+O 切换） |
| 常亮 | 不进启动参数，走 adb |
| 摄像头模式 | `--video-source=camera`；此时音频强制走 `mic`、不传 `--audio-dup`；控制不可用 |

## 八、连接管理（首期范围）

- **设备枚举**：解析 `adb devices -l`
- **USB**：检测到即列出，一键投屏
- **无线·已知 IP**：读取手机 IP（`adb shell ip route`，USB 已连时）或手动输入 → `adb tcpip 5555` → `adb connect <IP>:5555`
- **无线·系统无线调试配对**：手机「开发者选项 → 无线调试」显示配对码与端口 → 应用内 `adb pair <IP>:<端口> <配对码>` → `adb connect`
- **断连检测**：scrcpy 进程退出 + adb 设备轮询 → 提示并一键重连
- **记忆**：上次设备、连接方式、各开关状态写入 config.ini

## 九、输入法自动切换模块设计

- 随应用启动（**仅在应用运行期间**，不投屏时该线程几乎零开销）
- 判定：前台窗口 == scrcpy 窗口 → 切英文（`00000409`）；否则 → 切回中文（`00000804`）
- 频率：轮询 `GetForegroundWindow`，有投屏时 150ms、无投屏时 500ms（实测 CPU 开销可忽略）；二期可换 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 事件驱动
- 句柄绑定：启动后按 PID + 窗口类/标题轮询等待 HWND 就绪；**会话重启（音频档位 / 摄像头模式）后必须重新绑定**
- 收尾：停止投屏、切换会话失败、退出应用前都要还原中文布局
- 注意：目标窗口若以管理员权限运行，非提权进程的 `PostMessage` 会被 UIPI 拦截 → 应用保持普通权限运行，失败时记日志

## 十、分阶段实施计划与验收点

### 阶段 1（首期交付：完整可用版）
应用骨架 + 投屏嵌入 + 顶部工具栏 4 控件 + 设置 4 项 + 输入法自动切换 + 连接管理（USB / 无线 / 配对）+ 托盘

验收点：
1. 不连设备时启动应用：无后台常驻进程，退出后无残留
2. USB 一键投屏：画面正常、鼠标可点、**中文可直接输入**、音量/置顶/重连均生效
3. 无线：无线调试配对成功 → 投屏 → **拔掉 USB 线后仍正常**
4. 音频三档切换：切换后约 1 秒恢复，声音位置与选择一致
5. 设置四项逐项生效：熄屏/常亮不重连即生效，摄像头模式可进可回
6. 输入法：点投屏窗口直接打拼音出候选；点回记事本自动回微信输入法；**语言栏始终只有微信输入法 + 微软拼音**

截图（adb 抓帧）、录屏（`--record` 或 adb screenrecord）、画质档位（`-m` / `--video-bit-rate` / `--max-fps`）、更多工具栏按钮（返回/主页/最近任务/粘贴中文等）、多设备支持

## 十一、风险与坑

1. **无 .NET SDK**：只能 csc 直编，禁止引入 NuGet 依赖
2. **中文路径**：已验证可编译；子进程启动用 `ProcessStartInfo`（不经 shell），避免引号/转义问题
3. **scrcpy 窗口句柄**：窗口创建有延迟，需轮询等待，否则 `SetWindowPos` 失败
4. **无边框窗口**：需自实现拖动与最小化/关闭
5. **音频/摄像头切换需重启会话**：重启期间要禁用相关按钮并保留其它设置
6. **摄像头模式限制**：音频强制走手机麦克风、控制不可用
7. **无线稳定性**：Wi-Fi 抖动或手机熄屏可能断连 → 提供重连与自动探测
8. **UIPI**：向管理员权限窗口发消息/快捷键会失败
9. **adb**：端口占用、多设备需指定 serial
10. **内核版本绑定**：参数表与 scrcpy 版本强相关，配置里记录内核版本，升级内核需复核参数
